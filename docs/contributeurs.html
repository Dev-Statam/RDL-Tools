🛠️ Guide pour les développeurs

Comprendre vite le flux de RDL Tools avant de modifier le code.

Cette page résume les points qui comptent pour contribuer sans casser le comportement métier : ordre des scripts, insertion des boutons, surveillance du roulement et gestion des préférences.

Points de vigilance

  • L'ordre des scripts dans manifest.json est important.
  • Les boutons et la logique ICS sont injectés côté contenu.
  • Les réglages passent par le stockage du navigateur.
  • Le périmètre reste limité aux journées affichées par Service Voiture.

🏗️ Architecture fonctionnelle

Point d'entrée

js/content/content.js orchestre l'initialisation, récupère les réglages, installe les écouteurs et ajoute les boutons dans la page Service Voiture.

Utilitaires partagés

js/content/scripts/utils.js centralise les clés de stockage, les aides de date, le texte d'alerte et les fonctions réutilisées par plusieurs modules.

Génération ICS

Les classes ActivityDay et RestDay servent de structure aux données consommées par le générateur ICS.

Détection des changements

surveyorActivities.js observe les activités, les persistances et les modifications du roulement pour signaler les journées qui ont changé.

📚 Données et stockage

Clés actuelles

  • RDLToolsSynchedActivities dans storage.sync
  • RDLToolsSavedActivities dans localStorage
  • RDLToolsExtensionEnabled pour activer ou désactiver l'extension
  • RDLToolsSurveyorEnabled pour activer la surveillance des journées

Règle pratique

Si vous ajoutez une nouvelle donnée persistée, choisissez d'abord si elle doit suivre la synchronisation du navigateur ou rester locale. Cela évite les comportements inattendus entre plusieurs appareils.

🔎 Règles à respecter

1. Ne pas casser l'ordre des scripts

Le manifest charge les scripts dans un ordre précis. Les utilitaires doivent rester avant content.js, sinon l'initialisation peut échouer.

2. Garder le périmètre métier

L'extension ne doit traiter que les journées affichées par Service Voiture. Évitez d'ajouter des sources de données externes sans besoin clair.

3. Préserver la compatibilité navigateur

Vérifiez les modifications dans Chrome, Firefox et Firefox Mobile Android lorsque la fonctionnalité touchée dépend de l'interface ou du stockage.

4. Rester lisible

Les fichiers ont déjà une séparation claire entre template, logique métier, surveillance et options. Suivez cette organisation plutôt que de la mélanger.

🤝 Comment contribuer

Avant de coder

  • Lisez manifest.json pour comprendre le chargement des modules.
  • Regardez options/options.html pour les libellés de configuration.
  • Repérez les points d'injection dans content.js.

Après modification

  • Testez l'ajout du bouton de journée et du bouton de repos.
  • Vérifiez la génération ICS et la détection des changements.
  • Confirmez que les options restent cohérentes entre les navigateurs ciblés.
🧪 Bon réflexe : si vous touchez à la détection ou au stockage, validez d'abord le cas le plus simple, puis le cas avec personnalisation activée.
